# Mid-turn steering: design review findings (2026-11-23)

The design in DESIGN_NOTES.md ("Mid-turn steering: design") was reviewed by gpt-6.2-sol before any code was written. The owner parked the feature after this review. The findings below are the reviewer's text, kept as the starting point for a later attempt. `steer` stays refused; `restart`, `queue` and `auto` are unchanged.

Also found while measuring, and still open on main: when a backgrounded Agent finishes after the host's turn has ended, Claude Code starts a turn of its own, and the host can take that turn's result as its next message's.

VERDICT: CHANGES

**S-01 [blocker] — Claude can inject the steer into the wrong turn.** In the recorded background-agent run, N emitted its result at 8.934 s and a CLI-owned turn ran the same main-thread Stop hook at 12.328 s. If the host has yet to read N’s result, that hook can claim N’s pending file and inject it into the CLI-owned turn. The UUID bracket lets the host detect the mistake after delivery. `stop_hook_active` was false on the autonomous invocation, too. Require a provider-side check that binds the hook’s prompt to N **before** it claims the file, and use that same ownership check to attribute `init`, feedback and `result`. Keep Claude steering disabled until that check is proven for autonomous turns, folded notifications and compaction. **S-02 [blocker] — `taken` promises more than either receipt proves.** Codex can accept the RPC and Claude can emit the synthetic user line before the next model request. An interrupt, process exit or provider limit in that interval can leave the model without the steer. The recorded interrupt used PostToolUse and establishes hook-response ordering only. Define `taken` as confirmed insertion into the intended provider turn, with continuation and reply coverage conditional on that turn’s outcome, or require correlated evidence of model delivery before using the current definition. Codex’s `expectedTurnId` also fences a provider ID only. If `turn/start` joins an autonomous turn in the read/write gap, define whether that turn becomes N once it accepts N’s input, or require positive ownership before steering. [Measurements](/private/tmp/claude-501/-Users-peterbroomfield-agent-comms/8978d326-c70f-4b2a-8324-31064672a664/scratchpad/pr19/MEASUREMENTS.md:38) · [Codex adapter](agent_comms/providers/codex.py#L333)

**S-03 [blocker] — The Codex hold can strand the session or turn a real completion into a timeout.** Once `turn/completed` arrives, the adapter resets the provider turn, while a host that keeps N in flight leaves its normal timeout and cancellation paths armed. A healthy provider with a missing or malformed steer reply can therefore hold the queue indefinitely or make the host discard N’s observed result. Give the hold a distinct state with an immutable copy of N’s result, the exact request ID and write progress, and a bounded receipt deadline. Remove wholly unwritten requests immediately. Drain available evidence and fence ambiguous requests on timeout, cancellation, write failure or exit. Preserve N’s observed outcome through all of those paths and keep tracking autonomous Codex turns while the report is held. Specify whether a known early receipt frees the slot for another steer into N. S2 and S4 currently give different answers. [Codex completion](agent_comms/providers/codex.py#L605) · [Host timeout and failure](agent_comms/session_host.py#L1074)

**S-04 [blocker] — R3-01 and AC-08 need recovery rules on both sides of the report.** A fetch between completion and receipt must still find N locally owned, or today’s reconciliation can synthesize a lost end. A crash after completion but before reporting can also lose the held result. Adjacency in the pending list gives no atomicity because the reporter splits batches and can drop rejected events. Persist an indivisible, idempotent completion record and keep it until the hub confirms application. On silence, the hub can already settle N as `node_lost` and send that failure to the parent. A later transaction can then record S as `taken` while ignoring N’s actual end. Defer N’s final settlement for a bounded reconciliation window, or explicitly support `taken` with N’s result unavailable and define what the parent and `--wait` receive. [Node reporting](agent_comms/node_sessions.py#L395) · [Node reconciliation](agent_comms/node_sessions.py#L667) · [Hub loss settlement](agent_comms/hosted.py#L692)

**S-05 [blocker] — The state table loses decisive evidence and has no terminal path for permanent node loss.** Split P into journaled intent, published Claude file or Codex write progress, and durable evidence awaiting report. A crash before publication, a surviving withdrawal record, and an unsubmitted request can prove non-delivery. A missing file alone cannot distinguish those cases from a claim, and an arbitrary rename error cannot stand in for file absence. Use per-attempt evidence, drain matching output during teardown, and resolve after the old process is fenced. Arbitrate paired cancellation of N and S before recording a fate. The table’s `late → withdrawn` changes a terminal fate. Add close, cascade, orphaning and permanent node loss. Today close can fail S as ordinary queued work, emit a parent result, and discard later evidence on both sides. Retain a reconciliation record after closure and give it a bounded terminal path. Reserve `lost` for cases where the evidence is genuinely unavailable. [State table](DESIGN_NOTES.md#the-state-table) · [Host teardown](agent_comms/session_host.py#L843) · [Hub closure](agent_comms/hosted.py#L650) · [Ended-session reports](agent_comms/hosted.py#L1141)

**S-06 [blocker] — The rollback guarantees cover one side at a time.** If both binaries roll back after S reaches the provider and before its fate commits, the old hub lists S as ordinary queued text and the old node ignores the steer journal. It can deliver S again on the same database. Require a drain and fencing rule before rollback, or use a durable replay barrier both old binaries honor. For a single-side rollback, commit `steer_shown` before *every* text exposure, including the read-only listing path. Exposure alone also cannot justify “delivery unknowable” when durable evidence proves a fate. Finally, a synthetic legacy `turn_ended` can replace N’s reply and increment its turn count, beyond the documented parent notice. Define those effects and how a delayed legacy report is handled after re-upgrade, or require a drain for hub rollback too. [Hub listing](agent_comms/hosted.py#L842) · [Listing transactions](agent_comms/hosted_wake.py#L482) · [Ordinary handover](agent_comms/node_sessions.py#L924) · [Result accounting](agent_comms/hosted.py#L1073)

**S-07 [blocker] — A stale checkout reservation or binding can authorize a later write.** A parent steer gets `shown_at`, the node goes silent, and dispatch takes the released checkout. On return, existing listing code still exposes the task under its old reservation. If the node finds S `late`, ordinary handover can write it while dispatch owns the checkout. Revalidate and reserve transactionally after the silence boundary before releasing a late steer as ordinary work. Also fix **P × binding change**. P includes buffered and partial Codex writes, so “already handed” is too broad. Apply the current binding, lease and parent-access gates at publication and on each unfinished write. Keep later queue entries behind S until its disposition is safe to act on. [Checkout release](agent_comms/hosted_wake.py#L865) · [Task reservation](agent_comms/hosted.py#L928) · [Existing write gates](agent_comms/session_host.py#L1349)

**S-08 [blocker] — The spool is part of the trust boundary.** Modes `0700` and `0600` allow another shell-capable session under the same OS user to alter the spool. A replaced payload can enter another session as synthetic user feedback, and a recreated pending file defeats the one-rename argument. Exact matching afterward protects the report in some cases and comes too late to protect what entered the prompt. Scope the guarantee explicitly to an intact trusted spool, or isolate it from the processes covered by the guarantee. Specify validated absolute paths, shell-safe argument quoting, bounded regular-file I/O, and process-, turn- and attempt-scoped records. Keep parent text explicitly agent-authored even inside Claude’s user-role wrapper. I’d refuse steering for read-only Claude children initially. Their tool check cannot attest to a command hook, and a same-user sibling can still alter its input. [Trust design](DESIGN_NOTES.md#mid-turn-steering-design-2026-11-23) · [Claude access boundary](agent_comms/session_access.py#L19) · [Tool verification](agent_comms/session_access.py#L437)

**S-09 [should] — Specify Stop reentry, limits and coexistence before enabling the hook.** The recording shows a second Stop invocation with `stop_hook_active=true`, one result containing only the post-steer answer, and a `stop-hook-error` notification. It does not establish behavior at `--max-turns`, budget exhaustion, or with another Stop hook that blocks, delays or changes the feedback. Preserve existing hooks and define when coexistence disables steering, including settings reloads. Bound reentry and helper time within N’s original deadline. If joining reply segments, specify how multiple sequential steers, failed continuations and the reply cap work. Keep the steering capability probe separate from the mandatory bypass seal so it cannot break ordinary launches. Full launches currently keep their original settings. `auto` also changes behavior for existing callers who never explicitly request `steer`, and installing a Stop hook adds work at completion even when nobody sends one. **S-10 [should] — Define what senders can retrieve after the fate settles.** Keep the ordinary task frame for late and legacy delivery. The stored steer frame currently tells the child it is continuing N even when it starts a new turn. The parent’s existing `wait=true` looks for a result under S, which a taken steer never creates. Route that wait to N after fate settlement, or return the fate and target explicitly. For human `--wait`, define what happens when a later turn replaces the session’s only reply. Preserve the target and fate in the seven-day receipt, or state when those details expire, since message rows can be pruned after one day. Also disclose that a human steer into a parent-owned task can affect the reply delivered to that parent.
